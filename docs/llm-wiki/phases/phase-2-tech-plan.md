## 1. Overview

Phase 2 adds the **maintenance loop** on top of Phase 1's author/read loop. It ships three confirm-first
slash commands — `refine`, `prune`, `reorganize` — plus a deterministic **durability engine**
(`scripts/bundle_ops.py`) and one Doctor extension (**R4 link-health**). The defining guarantee is that
maintenance never rots the bundle: indexes and the log are *regenerated by a script* (not hand-edited),
and a concept move rewrites every inbound link so that a reorganization introduces **zero** newly-broken
links. No new primitive is introduced — three slash commands over native tools + the Phase 1 Doctor,
extended. No hooks, no MCP, no subagents (those are Phase 3).

Decisions taken (the simpler branch at each fork):
- **Atomicity = confirm-first + staged mirror, no auto-git.** Each command stages the operation in a
  `/tmp` bundle mirror, Doctor-gates it, shows a `diff`, and only on approval re-applies the same
  deterministic steps to the real bundle. Git history is the rollback; the command warns rather than
  committing on the user's behalf.
- **Prune/move log under `**Update**`.** OKF spec §195 states there is *no* deletion/move mechanism —
  "only `log.md` conventions" — and R3c sanctions only Update/Creation/Initialization. We did **not**
  invent new prefixes.
- **`capture`/`init` left untouched.** Retrofitting them onto the new engine was scoped out as a
  non-surgical change to working commands; it is a clean follow-up, not a Phase 2 requirement.

## 2. The durability engine — `scripts/bundle_ops.py`

Stdlib-only, deterministic, in-place. Four subcommands the maintenance commands compose. Conformance is
**not** its job — the Doctor remains the authority; the engine just makes the change and the Doctor
gates it.

| Subcommand | Contract |
|---|---|
| `index <bundle>` | Regenerate every `index.md` from concept frontmatter. The **preamble** (everything above the first `## ` heading) is preserved verbatim; the `## Concepts` / `## Sections` listings below are machine-owned. Root index keeps **only** `okf_version: "0.1"`; subdir `index.md` gets **zero** frontmatter. Concepts are sorted by title; the version is never copied into a non-root index. |
| `log-append <bundle> --kind K --message M [--date D]` | Insert `* **K**: M` newest-first under the date heading (`K` ∈ Creation/Update/Initialization), creating today's heading at the top if needed. `--date` (UTC default) keeps mirror and real-bundle writes identical. |
| `move <bundle> --from A --to B` | Physically move a concept (creating subdirs) and rewrite **every** inbound link across the bundle in **both** the relative (`./`) and bundle-relative (`/`) forms, **plus** the relative links *inside* the moved file (whose anchor directory changed). Indexes are **not** regenerated here — run `index` after. |
| `remove <bundle> --concept A` | Delete one concept (guarded: refuses reserved files and bundle-escaping paths). Inbound links are intentionally left for the Doctor to report (R4) — never silently rewritten away. |

**Why a script, not the model:** index regeneration and link rewriting are exactly the steps a model
gets subtly wrong at scale (a missed sibling bullet, a half-rewritten link form). Making them
deterministic is the whole point of "durable."

## 3. Doctor extension — R4 link-health

`doctor.py` gains **R4** (`WARNING` severity): every internal markdown link must resolve — `/…`
relative to the bundle root, everything else relative to the file's directory; external schemes and
bare `#anchor` links are skipped; a trailing-`/` target is checked as a directory. Per OKF spec §5
broken links are **tolerated**, so R4 is *report-only* and never changes the exit code. The previously
skipped `F-BL` fixture ("broken-link seam") is now an active R4 test.

**The reorganize gate is a pre/post diff, not a new flag.** `reorganize` records the set of R4 findings
*before* the operation, stages the moves, and requires the *after* set to be a **subset** of *before*
(`after ⊆ before`). Any link that was valid and is now broken is a regression and blocks the write. The
deterministic R4 detection lives in the script; the trivial set-subtraction lives in the command.

## 4. The three commands (all confirm-first)

Shared protocol: **resolve bundle → stage in a `/tmp` mirror → run engine ops + Doctor gate → show
`diff` + secret scan → on approval, land the gated result on the real bundle → re-Doctor → clean up the
mirror.** `allowed-tools` grants `Bash(python3:*)` plus the filesystem verbs staging needs (`cp`, `rm`,
`mktemp`, `diff`; `reorganize` also `rmdir` for emptied-subdir cleanup). "Land the gated result" is
*deterministic by construction*: `prune`/`reorganize` re-run their scripted engine ops (byte-identical
to the mirror), and `refine` **copies the gated concept back from the mirror** rather than re-authoring
it — so what the user approved in the diff is exactly what lands.

- **`refine`** — edit one concept's body/frontmatter in place (same path; preserves a non-empty `type`).
  Regenerates indexes (title/description may have changed) and logs an `**Update**`.
- **`prune`** — remove one concept via `bundle_ops remove`. Lists inbound links that will dangle (they
  are *reported*, not auto-fixed), regenerates indexes, logs an `**Update**`. Rollback = git.
- **`reorganize`** — plan `from → to` moves (incl. into new subdirectories), apply via `bundle_ops
  move`, regenerate indexes (new subdir `index.md` with zero frontmatter), log an `**Update**`, and gate
  on the R4 pre/post diff (`after ⊆ before`).

## 5. Tests (TDD)

- **Doctor corpus** (`scripts/fixtures/`, `run_fixtures.sh`) — un-skipped `F-BL` (R4 on a `./` dangling
  link) and added `r4_bundle_relative_link` (R4 on a `/` dangling link; a valid `/` link is clean).
  Now `pass=12 fail=0 skip=0`.
- **Engine golden corpus** (`scripts/ops_fixtures/`, `run_ops.sh`) — twelve cases asserting
  byte-for-byte output trees. `index`: `index_basic`, `index_subdir`, `index_no_title` (slug-humanized
  title fallback), `index_idempotent` (re-running on generated output is a no-op), `index_illegal_frontmatter`
  (normalizes a root index with a stray key and a subdir index that wrongly carried frontmatter).
  `log-append`: `log_append_today`, `log_append_newday`, `log_append_missing` (no existing log),
  `log_append_backdated` (an older `--date` is inserted *below* a newer section, preserving newest-first).
  `move`: `move_basic` (both `./` and `/` forms + the moved file's own links), `move_titled_link`
  (title / angle-bracket / fragment forms). `remove`: `remove_basic`. `pass=12 fail=0`.

## 6. Exit criteria — status

| Criterion | Status |
|---|---|
| Edit/prune/reorganize keep links + indexes correct automatically | ✅ engine + commands |
| A move leaves **zero** previously-valid links broken (Doctor pre/post diff), rewrites `./` **and** `/` forms | ✅ `move` + `r4` diff; proven on this repo's bundle (`reference/` move, R4 after = ∅) |
| Doctor **reports** (never deletes) broken links | ✅ R4 WARNING-only |
| Every regenerated index obeys the frontmatter rules (subdir = none, root = only `okf_version`) | ✅ `index` + Doctor R3a/R3b green |
| Every maintenance write is logged and reversible via diff | ✅ `log-append` + confirm-first `diff`, git rollback |

## 7. Deferred / follow-ups

- Retrofit `capture`/`init` onto `bundle_ops` for one code path (non-surgical; intentionally out of scope).
- Multi-file conformance as a hook is **Phase 3** — the per-call PreToolUse hook cannot gate a
  multi-file reorg atomically; it stays in command orchestration (consistent with the PHASE_PLAN).
- Consumer-mode link-health (report-only on *foreign* bundles) is **Phase 4**.
